## 两个问题的决策

**ECS／数组能否加速：能，但建议渐进实施。** 当前已有批量碰撞查询、LiDAR 分块射线内核、组 SFM 和 RVO 部分向量化。第一步应去除无用邻居列表和批量动作查找的平方级遍历，再做 SFM 有界分块、静态边界复用，最后验证小范围批量运动学。完整 ECS 权威存储的 API 成本较高，目前证据还不足以支持整体重写。

**MCP 能否连接本地 LLM 实时读取分析：能，已有稳定快照入口。** 推荐 `step()` 完成后生成带版本快照，MCP 只读暴露，Host 主动取数后交给本地 Gemma。当前一次摘要问答约 19.9 s，应异步解释观测并标明帧年龄。MCP 不需要等待 ECS，模型也无需先具备原生自动工具选择能力。

## 后续 PR 拆分草案

下面是计划中的工作单元，尚未创建对应 PR。每个单元应带独立的问题描述、差分验证、场景数据和可回退路径，不一次合入所有改造。

| 工作单元 | 范围与交付 | 依赖 | 验收门槛 | 复杂度 |
| --- | --- | --- | --- | --- |
| A：已定位的 Python 遍历成本 | 按需邻居输入、一次调用的动作目标映射，分别保留清晰提交 | 当前基线 | 轨迹／状态和动作异常语义一致；证明目标路径消除重复遍历，端到端计时改善 | 中 |
| B：只读快照桥接 | 帧契约、session／epoch、worker／发布边界、摘要、有界历史／事件 | 当前基线 | 旧快照不可变、跨帧一致、reset／reload 和并发读通过；bridge 开关开销可量化 | 中 |
| C：MCP 与 Gemma Host | 官方 SDK、stdio、只读资源／查询、Host 主动读取、HTTP 模型适配和超时 | B | 完整 MCP 握手与读取链路；固定 gold 问题；模型失联不阻塞仿真 | 中 |
| D：SFM 有界内存 | 先 ego 分块，再单独评估精确邻域候选 | 固定基准与参考语义 | 峰值内存受预算约束；同快照结果差分通过；不偷偷截断邻居 | 中 |
| E：静态几何复用 | LiDAR 边界缓存、版本失效；是否拆索引另测 | 生命周期回归 | 地图／多边形／洞／owner／等距命中一致，目标感知场景端到端改善 | 中至大 |
| F：受限数组后端 | diff／omni 纯运动 cohort、显式开关、对象权威与回落 | A、基准、充分差分测试 | 计入 pack／kernel／writeback 后仍达收益门槛；插件／噪声／接触保持原路径 | 大 |

建议先实施 A 和 B，随后 C 形成可演示的本地读取分析闭环。D、E 根据真实场景瓶颈取舍；F 必须在局部优化之后再次论证。不将完整 ECS、原生模型工具调用、GPU 仿真、自动控制和 UI 改造绑定成同一个 PR。

## 进入实现前已确定的契约

- 默认保留现有逐对象行为的顺序观测；共享快照行为作为显式模式讨论。
- 公共对象 ID 不等于数组 slot；对象身份包含环境和生命周期版本。
- 只在完整 tick 边界复制状态；MCP handler 不直接跨线程操作 EnvBase。
- 首版 MCP 只读；模型建议不自动执行为运动命令。
- MCP／模型依赖为可选 integration；普通仿真安装保持轻量。
- 以可重现的端到端收益决定是否扩大 ECS 范围；小场景、接触、插件和随机流是兼容性门槛。

## 仍需在实现阶段验证的项目

尚未测得新 ECS 后端的收益，也未实施完整 MCP 服务。当前短基准不代表所有规模、地图、接触和渲染场景；Gemma 仅成功执行了一次基于事实摘要的 smoke probe，不能推出一般诊断可靠性。当前 vLLM 工具 parser 的选择／配置、模型长任务延迟、用户实际主要场景的规模，以及正式性能门槛中的重复运行，都留在后续实现实验中。
