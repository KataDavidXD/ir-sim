# ECS 与数组化加速方案

> 状态：提案，尚未实现。基线提交与模块说明见[架构评审](architecture-review.zh-CN.md)。本文所有性能目标均为后续验收门槛；没有把当前实现之间的差异称为“ECS 实测加速”。

## 1. 是否值得做

**值得采用数据导向的批处理，暂不建议完整替换现有对象模型。** ECS 解决实体标识、组件存储和系统调度；数组加速来自连续数值数据、批量运算、缓存复用和减少 Python 调用。两者有关联，但不是同一件事。

| 路线 | 预期价值 | 成本／限制 | 建议 |
| --- | --- | --- | --- |
| 消除重复列表与目标查找 | 直接移除已定位的 O(N²) Python 遍历 | 插件参数与动作语义要保留 | 首先做 |
| 有界 NumPy 工作缓冲区＋按模型批处理 | 减少小数组和逐对象内核开销 | pack／writeback 仍有 O(N) 成本 | 分阶段验证 |
| 数值内核局部编译 | 适合稳定、分支较多的标量循环 | 增加依赖／编译／平台维护 | profiling 后决定 |
| 完整 ECS 权威存储 | 适合长期数千实体、多种系统共享数据 | 改写可变数组 API、生命周期、插件和几何适配 | 暂缓，单独 RFC |
| GPU／JAX／PyTorch 全量迁移 | 大规模纯数值批次可能受益 | GEOS 在 CPU、数据传输、变长几何、与 Gemma 争显存 | 不作为首版 |

优先场景是数百至数千个相近模型、headless 执行、多次规划／学习 rollout。少量机器人加 Matplotlib GUI、复杂接触或复杂地图的场景，主要成本可能在其他地方。应分别给出场景结果，不能承诺统一的倍数。

## 2. 性能证据应该怎样解释

当前快照、阶段耗时、调用次数和内存探针见[证据说明](evidence/README.md)及原始 JSON。测量固定 seed、关闭绘图，单列 `step`、快照复制、`to_dict`、JSON 编码；这只是本机基线。

已有组 SFM 比逐对象 SFM 更快，并不能单独证明迁移到 ECS 的收益：前者已经数组化，而且其共享快照的更新语义不同。完整快照也不是免费操作，MCP 的发布开销需要与仿真基准分开记录。

采用 Amdahl 定律约束收益判断：

```text
整体加速 = 1 / ((1 - f) + f / s)
f = 被优化部分原先占整体耗时的比例
s = 该部分的加速倍数
```

例如，**假设**运动学只占 20%，即使该内核变快 10 倍，整体也只有约 1.22 倍。cProfile 会显著放大 Python 调用开销，适合定位结构性成本；不能把它的累计耗时占比直接等同于未插桩的真实耗时占比，也不能相加嵌套的累计时间。

## 3. 第一阶段：先移除可证明的重复工作

### 3.1 按需提供邻居

源码路径：`ObjectBase.gen_behavior_vel()`、`external_objects`、`Behavior.gen_vel()`。

内置 dash 不需要邻居，但当前仍在每个对象行为调用前构造全量外部列表。可让内置注册项携带 `requires_neighbors` 能力，或提供惰性的查询上下文。自定义行为在未声明能力时继续接收原有列表，避免让依赖列表类型／顺序的插件静默失效。

验收首先要求 dash 路径不再逐对象扫描 N 个 ID，并对同一 seed 的状态／到达／碰撞／轨迹作差分。RVO／SFM 仍需邻居，不能通过删邻居来制造性能提升。只做缓存时还要保留成员顺序、unobstructed 过滤以及逐对象观测新旧状态的现有语义。

### 3.2 一次动作调用建立目标映射

源码路径：`util/decorator.py::_target_positions()`、`util.py::find_object_by_identity()`。

一次归一化先建立 ID／名称到列表位置的映射，再解析 K 个目标。第一版用每次调用的局部映射即可，不必立即引入跨帧缓存失效。要求保留未知目标的报错、非连续 ID、dict 动作、重复目标按原顺序覆盖、单动作广播、动作数量不匹配和连续目标语义。

该优化独立于 ECS。公共 ID 不等于数组下标，也不等于 `self.objects` 的位置；删除对象以后尤其如此。

### 3.3 复用静态边界

源码路径：`ray_casting_2d.py::_gather_obstacle_edges()`、`boundary_segments()`。

当前数值射线内核已经分块，候选对象边界却可能为每个传感器重复提取。为真正静态的几何缓存原始线段／世界线段；动态形状按 geometry version 失效。`set_state`、`set_original_geometry`、接触位移／旋转、reload 和删除都必须覆盖。

地图已有内部索引，应继续按附近边界查询，不能为了缓存直接展开整幅地图。重用缓存要保留洞、MultiPolygon、线对象、owner ID 以及等距命中的原有优先顺序，避免改变 LiDAR／FMCW 返回的对象速度。

## 4. 第二阶段：有界数组工作集

第一版仍让 `ObjectBase` 拥有权威状态；每步为满足条件的对象打包工作缓冲区，批量计算，再通过统一回写边界同步几何、缓存和轨迹。这样能直接测得 pack／kernel／writeback 的总收益，再判断是否值得把权威存储迁入 ECS。

以下是**拟议布局**，不是已经存在的 API：

| 数据 | 拟议形状与类型 | 处理方式 |
| --- | --- | --- |
| 身份 | `entity_id[C] int64`、ID 到 slot 映射 | 与顺序／密集槽位分离；按环境隔离 |
| 位姿 | `pose[4, C] float64`、`state_dim[C]` | 通道连续的 SoA 工作缓冲，保留 Ackermann 第四维 |
| 动作／速度 | `action[3, C]`、`velocity[3, C] float64` | 按运动学约定解释，不假定全是世界速度 |
| 限制 | `vel_min/max[3, C]`、`acce[3, C]` | 广播和掩码保留原限幅顺序 |
| 标志 | `alive/static/stopped/arrived/unobstructed[C] bool` | 按系统构造掩码，不反复访问 Python 属性 |
| 质量参数 | `mass/friction/inertia/restitution[C] float64` | 初版仍供原 contact 求解器使用 |
| 模型 | `kinematics_kind[C]`、`shape_kind[C]` | 内置类型分组；未知模型回落 |
| 目标／行为配置 | 当前目标数组＋对象侧队列／注册项 | 变长数据不强塞进固定矩阵 |
| 几何／地图 | 句柄、版本、变长线段池、offset／owner 数组 | GEOS 几何继续由现有适配器维护 |
| 传感器 | 每类独立批次，beam 数量按桶或 offsets 表达 | 避免为所有传感器按最大 beam 数补零 |

`state[N, 4]` 按行连续的矩阵属于 AoS 风格布局；它也可向量化，但不能仅凭“用了 ndarray”就称为 SoA。这里用 `[channel, capacity]` 让单字段连续；按 chunk 处理，实际 stride 和 gather 成本要实测。

默认 `float64` 与基线保持一致。`float32` 需要单独定义误差、碰撞边界和训练复现影响；不能与架构重构混在同一个性能结论里。

### 4.1 第一批支持范围

先覆盖确定性、无噪声的 diff／omni，动作由调用方或受支持的组行为在运动前产生。没有自定义 pre／mid／post hook、没有 contact、没有 external step 的纯运动 cohort 最易验证。omni_angular 与 Ackermann 后续增加。

含自定义行为、运动学、处理钩子或跨对象读写时，默认整段保持原顺序路径。混合场景不能把部分对象提前批量回写，导致剩余对象观察到与原先不同的状态。只有明确证明独立的阶段才可以分组重排。

### 4.2 运动学必须保持的约定

- diff：前进速度沿当前 heading；角度 wrap 的区间和端点保持一致。
- omni／omni_angular：动作中的前两维是 body frame；需要依 heading 旋转到 world frame。
- Ackermann：当前 yaw 积分使用当前 steering state；`steer` 模式最后更新转向状态。不能按常见自行车公式擅自换成新转角参与本步积分。
- passive：世界速度和驱动对象的动作布局不同，仍由原 Handler 执行滑行／摩擦。
- 保留速度／加速度裁剪、stop／arrive、角度、目标切换、轨迹和缓存失效的顺序。

### 4.3 为什么暂时不让数组成为唯一权威

当前 `obj.state` 返回可变数组。权威 SoA 若返回临时 gather，用户对 `obj.state[...]` 的修改不会回到存储；若返回零拷贝视图，扩容、槽位迁移和外部持有旧引用又会产生生命周期问题。第一阶段保留对象权威，可以避免同时改变这套契约。

后续若确实需要完整 ECS，应单独决定：公开 getter 返回副本／只读视图还是可写视图；结构变更何时生效；稳定 chunk／generation handle 如何设计；如何兼容 setter、直接数组写入和插件。不能出现对象与数组同时充当权威的长期状态。

## 5. SFM：先限制峰值内存，再减少候选数量

当前 `SocialForceModelBatch.social_force()` 的分配规模是 O(N(N+M))，并有多份二维临时矩阵。`obstacle_force()` 也受 N×墙体线段数影响。局部范围过滤并未避免这些分配。

推荐两步：

1. **按 ego 行分块**：每次计算 C 个成员对全部邻居，立即归约到输出力。可将成对临时矩阵限制为 O(C(N+M))；墙体路径也设独立内存预算。先保留同一快照、全部相互作用和参数语义。
2. **精确邻域查询**：用均匀网格、KDTree 或合适的树为每个 ego 找范围内候选，以 CSR／edge list 表达，再做相同数值公式。邻居顺序固定，不能擅自给每个实体只留 K 个邻居。若场景稠密，所有实体互相在范围内，最坏情况仍是 O(N²)。

原始内存探针记录在证据 JSON。不要把 10,000 个实体的全矩阵实验直接用于首轮验证：单个 `[10000, 10000] float64` 就约 800 MB，`[..., 2]` 再翻倍，多份中间结果会继续增加。这里是形状推导，未声称跑通了万人场景。

## 6. 接触、碰撞与渲染的边界

接触求解器已经把凸分片和累计位移放在内部工作集，使用按 anchored order 的 Gauss–Seidel sweep，负载可沿接触图传播。对共享刚体的所有 pair 同时计算和写回会改变收敛、摩擦、堆叠和力的结果。首版保留原求解器；后续可评估不共享实体的约束集合、分片内核和图结构，但那是算法设计任务。

碰撞状态已批处理，不能再把“将逐对碰撞改为向量化”当作新方案。静态／动态 STRtree 拆分只在静态占比高且 profiling 支持时进行；需要新的 index-to-entity 映射，不能破坏当前传感器假定的树位置与 `objects` 对齐。

Matplotlib 的渲染和布局不因 ECS 自动加速。所有性能报告至少分为 headless `step`、离屏 render、交互 render；不把关闭显示获得的改善计作算法加速。

## 7. 参考与新运行时的调度契约

```text
输入解析／生命周期变更边界
  → 原有动作优先级
  → 行为（默认保留顺序观测；同步观测仅显式选择）
  → 受支持的运动批次或原对象路径
  → 几何同步和空间索引
  → 原有 contact 求解
  → 传感器
  → 世界时钟／迷雾
  → 碰撞／到达／状态
  → 发布完整帧快照
```

上述是后续的系统边界设计；实际函数的细节顺序以基线和差分测试为准。插入 ECS System 不能省略不在热路径图中显眼的副作用。

RNG 必须特别处理：现有 seed 对应特定调用顺序。按运动学重排噪声抽样会改变每个对象拿到的随机数。初版噪声场景回落；如果以后引入每实体随机流，需作为新模式说明旧 seed 不能逐位复现，而不是把它当作透明优化。

## 8. 基准矩阵和验收门槛

| 维度 | 后续代表场景 | 重点 |
| --- | --- | --- |
| 规模 | N=1／10／100／500／1000；更大规模逐级验证 | 小场景回归、拐点和增长阶数 |
| 动作 | dash、显式多 ID、组行为、插件 | 重复遍历与分组适配 |
| 行为 | 个体 RVO／SFM、组 SFM、可选 ORCA | 语义不同的模式分别报告 |
| 几何 | circle、polygon、compound、linestring、栅格 | 不只用圆形证明普遍收益 |
| 感知 | 0／1／4／更多 LiDAR，180／360／1080 beams | 线段缓存、owner、盲区和等距命中 |
| 物理 | stop／unobstructed／contact | 回落和原接触结果 |
| 生命周期 | reset／random reset／reload／增删对象／external mode | ID、缓存和分组一致性 |
| 可复现 | 固定 seed，无噪声／有噪声 | 数值误差与随机流契约 |

每个目标场景独立 warm-up、至少 5 次运行，每次不少于 200 步，并报告中位数、p95、RSS 峰值、对象／候选／线段数、依赖版本。当前 25 步诊断用于定位，不能代替这个发布门槛。

提议的首轮性能准入线：目标场景端到端 `step` 中位数至少改善 20%；小场景无超过 5% 的稳定退化；SFM 分块峰值受预算约束；不能通过减少精度、邻居、传感器频率或改变接触模式达到指标。若未达到，就只合入已证明有益的局部优化，不为 ECS 结构本身付出持续维护成本。

正确性以 scalar／reference 路径差分为主：确定性纯运动初始建议 `atol=1e-10, rtol=1e-9`，碰撞／到达／目标队列／对象身份逐项一致。长轨迹和边界几何场景不能只看最终均方误差；接触、等距射线、±π、停止时刻和到达时刻有专门验收。容差须经基线测量确认，不能直接作为所有模型的统一保证。

## 9. 建议落地顺序

1. 固定参考场景与记录方法，补充身份／生命周期回归。
2. 单独提交邻居按需获取与动作映射优化；保留完整对象执行路径。
3. 单独提交 SFM 有界分块；再评估空间邻域和静态线段复用。
4. 引入受限数组运动批次与显式开关，默认保持现有后端。
5. 用端到端收益、API 成本和真实规模决定是否进入完整 ECS RFC。
